## 二、应用本质

基于 **mihomo（Clash.Meta）内核**的付费代理客户端，"网吧云"（netbarcloud）后端马甲之一：

- 内核：libclash.so = 定制编译 mihomo（`Meta_Alpha_4c10d42_250918`），被注入 4 个 cgo 导出函数（getSS1/getSS2/getRegisterKey/getRegisterKiv）——上游 mihomo 没有，属定制模块
- Java 框架层 `com.cncat.vpn.*` 来自 CNCat VPN，本应用是**换皮**（JNI 桥接类仍为 `com.cncat.vpn.core.bridge.Bridge`）
- 同族马甲：八爪鱼(bazhuayu)、太子(taizi)、云梯(yunti)、鹰猫(yingmao)，共享 `/netbarcloud/vpn/*` API，共享阿里 OSS / GitHub / AWS 三 CDN 分发加密配置
- UI：Jetpack Compose；支付：Stripe / 支付宝 / 微信 / 点卡 / 比来

## 三、加密体系（核心成果）

### 3.1 密钥分发机制

```
APK 签名 DER → SHA256 hex（作为 name）
   ↓ libbridge.so(JNI 壳) → libclash.so(Go 定制函数)
getRegisterKey(name) = M8T74hb17KR183b6   注册体 AES-128 key
getRegisterKiv(name) = 242itTn000C480h1   注册体 IV
getSS1(name)         = rwb6c4e7fz$6el%0   响应/域名加密 key
getSS2(name)         = z1b6c3t4e5f6k7w8   响应/域名加密 IV
```

特点：**密钥按签名绑定**——重打包即失效（anti-tamper）；Go 层符号已剥除（无 .gopclntab），动态 hook 是最短路径。

### 3.2 三处应用（均已实测验证）

| 场景 | 算法 | 验证结果 |

## 七、反分析与风险点

1. **多进程隔离**：几乎所有 Activity `android:process=":background"`，主进程极短命——常规 frida spawn/enumerate 失效，需直连 pid attach
2. **冻结陷阱**：退后台被 freezer 冻结后 ptrace stop 超时，需 force-stop 后再 attach
3. **权限越界**：READ_SMS / READ_CONTACTS / READ_CALL_LOG / ACCESS_FINE_LOCATION / QUERY_ALL_PACKAGES / MANAGE_EXTERNAL_STORAGE——远超 VPN 需求
4. 无 SSL Pinning + 信任 user CA + 自签证书：MITM 零门槛
5. 默认密码 123456 + 自动注册 + 硬编码 Basic 凭证：可批量化

## 八、到期/会员限制点（破解依据）

- `UIMainActivity`：`checkLogin` 响应 `data.expired`（null 视为 true）→ 写入 MMKV `expired`
- `HomeFragment.g()`：读 MMKV `vpn_valid_period` 与当前时间比较，**返回 true 表示已过期**，触发 12+ 处 `expired_recharge__layout` 充值弹窗并阻断启动
- `UserData`：`expired` / `needBuy` / `openVpn` / `vpnExpireTime` 四个字段共同决定 UI 会员态
- 密钥按签名索引：`Clash.getSS1/SS2/getRegisterKey/getRegisterKiv` 包装层是唯一入口

## 九、结论

com.yingmao.clash 的"设备绑定 + AES 加密通信 + 动态域名"体系已被完全打通：**签名→密钥→注册/响应/域名三级加密全部实测通过**；配合无 Pinning、明文凭据与越权权限，该客户端在协议层与数据层均无实质安全边界。改造后的无限制版本见《无限制改造报告.md》。
