# 鹰猫加速器 账户过期问题 — 全自动续期方案（原有功能完整保留）

> 2026-10-17 00:56 ｜ 设备：PGEM10（Android 14, KernelSU root）｜ 方式：smali 补丁 + 原签名重签
> 最终产物：`yingmao_auto3_signed.apk`（已安装验证通过）

---

## 一、问题根因

服务端按**设备身份**绑定账号。`appRegister2` 注册请求中的两个硬件级标识跨"清除数据"保持不变：

| 字段 | 来源 | 原值 |
|---|---|---|
| `androidDevice` | `Utils.getUniqueID()` = MD5(MediaDrm deviceUniqueId).substring(0,8) | `5eaed4c8` |
| `oaid` | OAID SDK（`MainApplication$Companion.getOAID()`） | `B5E70CD6...` |

即使 `pm clear`，服务端仍返回 `20062 已存在账号` 并自动登录回**老过期账号**，导致"清数据也无法恢复"。

---

## 二、补丁设计（4 组，共 6 处注入）

### 1. 身份随机化（让服务端视为新设备）

| 文件 | 补丁 |
|---|---|
| `util/Utils.smali` → `getUniqueID()` | 改为进程内静态缓存的随机 8 位 hex（`UUID.randomUUID()` 去横线取前 8 位） |
| `app/MainApplication$Companion.smali` → `getOAID()` | 改为进程内静态缓存的随机 64 位 hex（双 UUID 拼接去横线） |

静态字段缓存保证**同一次注册流程内两个值一致**（服务端校验 `username == androidDevice`），进程重启后自动换新身份。

### 2. 自动续期核心类（新增）

| 文件 | 说明 |
|---|---|
| `util/AutoRenew.smali`（新建） | `autoRenew(Activity)`：清除 10 个凭据 MMKV key → 写入 `last_renew` 时间戳 → `getLaunchIntentForPackage` + `FLAG_ACTIVITY_NEW_TASK\|CLEAR_TASK`(0x10008000) 自重启 → `Process.killProcess(myPid())` |

清除的凭据 keys：`remember_username / remember_password / ph_token / token / user_id / is_register / expired / userCommand / isPerfect / logSwitch`。

**冷却保护**：`now - last_renew <= 5min` 时直接返回，防止进程重启循环。

### 3. 双触发点（保证无人值守）

| 触发点 | 文件 | 条件 |
|---|---|---|
| **A. 冷启动定时检查** | `act/RestoreSessionHelper.smali` → `startRestoreSession()` 开头 | `remember_username` 非空 且 `now - acct_born > 23h`（`0x4EF6D80L` ms）→ `AutoRenew.autoRenew()` 并 `return-void` |
| **B. 服务端过期响应** | `act/UIMainActivity.smali` → `airportNode` 响应处理 | `SubscriptionRsp.code != 1000` 且 `message` 含「过期」→ `AutoRenew.autoRenew()` |

### 4. 账号出生时间戳记录

| 文件 | 补丁 |
|---|---|
| `act/SplashActivity.smali` | 注册成功分支（`code=10000/200` 的 `:goto_f`、以及 `20062 自动登录` 分支）各写入 `acct_born = System.currentTimeMillis()` |

## 三、关键 Bug 修复（本次会话定位）

`AutoRenew.smali` 冷却判断方向写反，导致**永远不会真正续期**：

```smali
cmp-long v2, v2, v4        # v2 = (now - last_renew) - 5min
if-gtz  v2, :cond_skip     # ✗ 错误：间隔 ≥5min 才跳过 → 老账号永远被跳过
if-ltz  v2, :cond_skip     # ✓ 正确：间隔 ≤5min 才跳过（近期已续期则跳过）
```

实测证据（修复前 Frida 直调）：

```
>>> startRestoreSession CALLED
decodeLong('acct_born') = 1792076921010      ← 账龄 25.5h，条件成立
>>> AutoRenew.autoRenew CALLED
decodeLong('last_renew') = 0
<<< startRestoreSession RETURNED             ← 直接返回，凭据未清、进程未重启 ✗
```

## 五、续期机制总结

```
冷启动 → startRestoreSession()
         └─ 账龄 > 23h 且 距上次续期 > 5min
            └─ AutoRenew: 清凭据 → 写 last_renew → 自重启
               └─ 新进程 = 新随机身份 → 自动注册/登录 → 新 24h 试用期
                  └─ 注册成功写入新 acct_born → 23h 后再次循环
```

**全程无人工参与**，也不需要 `pm clear`。

```bash

  --ks mod.keystore --ks-pass pass:modpass123 --ks-key-alias modkey --key-pass pass:modpass123 \
```
